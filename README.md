# Freesound Agent

An AI agent that explores taxonomic biases in the [Freesound](https://freesound.org) audio commons through five tools: search, metadata retrieval, spectral analysis, tag-distribution statistics, and a RAG-based academic knowledge base.

Built with Claude's native tool use, the `freesound-api` client, `librosa`, and ChromaDB.

## Motivation

Freesound is the source database behind major audio ML datasets such as FSD50K and ESC-50. (FSD50K uses the AudioSet ontology for its labels, but its audio comes from Freesound; AudioSet's own clips come from YouTube.) Its content is generated by a decentralised community of contributors, each labelling uploads with their own folksonomy, so the database reflects the recording culture of its contributors as much as the "sounds of the world." This agent surfaces those patterns: who uploads what, which tags co-occur, how durations cluster, and how the observed biases map onto the published research on Freesound's folksonomy.

## Setup

### Requirements

- Python 3.12+
- ~1.7 GB disk: ~1.6 GB of Python dependencies (PyTorch, pulled in by `sentence-transformers`, is ~600 MB of that) plus ~90 MB for the embedding model. Measured on macOS (Apple Silicon); on Linux, the default PyTorch wheels bundle CUDA libraries and need several GB more.
- A Freesound API token ([apply here](https://freesound.org/apiv2/apply/))
- An Anthropic API key

### Install

```bash
git clone https://github.com/kyuchia/freesound-agent.git
cd freesound-agent
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

### Configure API keys

Create a `.env` file in the project root:

```
ANTHROPIC_API_KEY=sk-ant-...
FREESOUND_API_KEY=...
```

### Download the papers for the RAG knowledge base

The papers are not committed to this repo. Please download them yourself and place them in `papers/`:

| Paper | Download link | Filename |
|---|---|---|
| Martínez et al. 2009 | [PDF](http://www.mtg.upf.edu/files/publications/SMC09_emartinez_ocelma_msordo_bdejong_xserra.pdf) | `martinez_2009_extending_the_folksonomies_of_freesound_org_using_content_based_audio_analysis.pdf` |
| Font et al. 2012 | [PDF](https://ismir2012.ismir.net/event/papers/073_ISMIR_2012.pdf) | `font_2012_folksonomy_based_tag_recommendation_for_online_audio_clip_sharing.pdf` |
| Fonseca et al. 2017 | [PDF](https://archives.ismir.net/ismir2017/paper/000161.pdf) | `fonseca_2017_freesound_datasets_a_platform_for_the_creation_of_open_audio_datasets.pdf` |

All three are open-access academic publications from the UPF Music Technology Group.

### Build the RAG index (one-time)

```bash
python knowledge.py --rebuild
```

First run downloads the `all-MiniLM-L6-v2` embedding model (~90 MB) and indexes ~45 chunks across the three papers. Takes about 30 seconds after the model is cached.

## Usage

### Interactive CLI

```bash
python agent.py
```

### Example queries

**Pure Freesound API tools:**
```
> Find 5 rain recordings longer than 30 seconds
> Analyze the audio features of sound #12345
> Compare spectral features of thunder vs rain recordings
```

**Tag-distribution analysis:**
```
> What tags co-occur with "bird"? Any bias patterns?
> Who are the top uploaders for "forest" sounds?
```

**RAG-grounded questions:**
```
> Why is Freesound's tag distribution uneven?
> What does "folksonomy" mean in Freesound research?
> What's a "narrow folksonomy"?
```

**Combined: empirical data + literature:**
```
> Analyze the tag distribution for "bird" and tell me if the uneven
  pattern is consistent with what the Freesound research literature
  describes.
```

### Inspect the knowledge base

```bash
# dump all chunks with their section labels (no embedding needed)
python knowledge.py --inspect

# query the index directly
python knowledge.py --query "what is a folksonomy?" --top-k 5
```

## Evaluation

A 13-query retrieval evaluation lives in `eval.py`. It tests three categories:

- **Single-source (6)**: top-1 must match the expected paper
- **Multi-source (4)**: top-3 must contain at least one expected paper
- **Out-of-scope (3)**: top-1 distance must exceed a confidence threshold

```bash
python eval.py                  # terminal output only
python eval.py --write-report   # also writes eval_results.md
python eval.py --verbose        # show all retrieved chunks per query
```

Latest results: see [`eval_results.md`](./eval_results.md).

The evaluation surfaces both retrieval strengths (90% in-scope hit rate, MRR ≈ 0.9) and methodological limits (absolute distance thresholds are fragile; in-scope vs OOS *separation* is the more informative signal). Findings and follow-up work are documented in the report itself.

## Tests

Offline unit tests for the agent's tool-use loop live in `tests/`. They replace the Anthropic client with a scripted fake and block network access, so they need no API keys, no papers and no RAG index:

```bash
pytest
```

They check that a failing tool becomes an `is_error` tool result, that a failed or interrupted turn is rolled back so the next turn still works, that the per-turn tool-round cap forces a final answer, and that `max_tokens` / `refusal` stop reasons leave a valid conversation history.

## Design notes

### Why these three papers specifically

The knowledge base is scoped to peer-reviewed publications from the UPF Music Technology Group, the research team that built and maintains Freesound. This keeps the RAG authoritative and on-topic: every passage is about the specific database the agent interacts with, rather than about audio ML in general.

### Embedding choice

`all-MiniLM-L6-v2` (sentence-transformers, local). Chosen for zero-setup (no API key) and adequate quality at this scale (~45 chunks, primarily factual queries). The collection wrapper in `knowledge.py` makes it straightforward to swap for Voyage, OpenAI, or Cohere embeddings later.

### Chunking strategy

Section-aware: headings like `4.1 Tag behaviour` become chunk boundaries. Sections longer than 2,500 characters are split at blank-line breaks in the extracted text, but pypdf produces few of these (mostly at page boundaries), so some chunks stay longer than that; the largest is about 4,700 characters. Every chunk carries metadata (`source`, `paper_title`, `authors`, `year`, `venue`, `section`) so the agent can cite passages as _Martínez et al. (2009, Section 4.1)_.
